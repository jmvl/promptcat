# Codebase Patterns

## Reusable Patterns Identified

### IndexedDB Wrapper Pattern
- **DB Module**: Encapsulates IndexedDB access with promise-based API
- **Pattern**: IIFE exposing `{open, getAll, get, put, bulkPut, remove, bulkRemove, clear, getStorageUsage, STORES}`
- **Usage**: Single database with multiple object stores, keyPath-based access

### Encryption Service Pattern
- **CryptoService**: AES-GCM encryption with PBKDF2 key derivation
- **Encryption Output**: `{ ct, iv, salt }` object (base64 encoded)
- **Password Validation**: Encrypted check value `passwordCheck` stores `encrypt(String(id), password)`
- **Session Caching**: Optional in-memory storage of passwords for "remember this session"

### Lockable Entity Pattern
- **Entities**: Prompts (individually lockable) and Folders (lockable with inheritance)
- **Fields**: `isLocked` (boolean), `passwordCheck` (encrypted ID)
- **Behavior**: When folder locked, all contained prompts inherit encryption with same password
- **UI**: Lock switch disabled in details view if folder is locked

### Settings Store Pattern
- **Schema**: `{ key: string, value: any }`
- **Usage**: Simple key-value store for UI preferences (e.g., `panelWidth`)
- **Access**: Get by key, not by id

### Bulk Operations Pattern
- **Transaction**: Single `readwrite` transaction for batch operations
- **Bulk Put**: `items.forEach(item => store.put(item))` then `transaction.oncomplete`
- **Bulk Remove**: `keys.forEach(key => store.delete(key))` then `transaction.oncomplete`

## Pattern Usage Guidelines
- Use DB module for all IndexedDB access
- Use CryptoService.encrypt(text, password) for sensitive data
- For validation, compute `CryptoService.encrypt(String(entityId), password)` and compare against stored `passwordCheck`
- Clear `decryptedCache` when closing prompt details view to avoid memory leaks
- Store UI state in separate `settings` store, not in entities
